# Hindi review records -- Gate 5a

Two committed records, both keyed by the same dotted `group.key` path
`scripts/build_hindi_review_corpus.py` walks out of `i18n.HI`. Together they
must account for every leaf string in `i18n.HI` -- `tests/test_hindi_review_pinning.py`
checks this mechanically and fails closed if a string is in neither, or in both.

## `unreviewed.json`

Auto-generated by `scripts/generate_hindi_unreviewed_list.py` -- **never hand-edit**.
Every entry: `{"key": "...", "reason": "..."}`. Today every leaf string is here,
each with the same reason: no Hindi reviewer has been engaged yet (Gate 5a
Deliverable 2 is not started). Regenerate after any change to `i18n.HI`:

```
.venv/bin/python -m scripts.generate_hindi_unreviewed_list
```

## `signed_off.json`

Hand-maintained. Empty until a real Hindi speaker reviews a string. Once
populated, each entry names who approved it and when -- the design doc's own
exit criterion for Deliverable 4 ("a committed record naming the reviewer and
the date"):

```json
{
  "key": "verdict.Low",
  "reviewer": "<full name>",
  "date": "YYYY-MM-DD",
  "hindi": "<the text approved -- the current i18n.HI string, or its replacement>",
  "comment": ""
}
```

Moving a key from `unreviewed.json` to `signed_off.json` is the unit of
progress this package sets up but does not perform -- see
`docs/superpowers/specs/2026-09-01-persona-truth-design.md` §5, Deliverable 2/3.
